# 来源应用图标跨设备同步需求

> 状态：阶段 A Windows 与共享层已实施并验证，阶段 B macOS 原生采集待实施。
>
> 本文是“来源应用图标跨设备一致显示”的唯一需求与验收依据。实现不得以本机安装路径相同、目标设备已安装同一应用或平台能够再次解析原生图标为前提。

## 1. 背景

当前主窗口和快速窗口能够根据来源应用的本机 EXE、Windows AUMID 或 macOS App Bundle 解析原生图标。但是同步协议只传来源名称和稳定身份，不传 EXE/App Bundle 路径，也不传图标像素。因此普通 Win32 应用、未安装应用和跨平台来源在另一台设备上只能显示通用图标。

目标是让来源设备已经成功解析出的应用图标随剪贴板记录加密同步。目标设备不依赖应用安装位置，也不要求安装同一应用，仍能显示来源设备记录下来的图标。

## 2. 范围

本功能分两个阶段实施：

1. 阶段 A：Windows 与共享层。
   - 完成共享模型、SQLite、同步协议、Blob 生命周期、ViewModel/UI 消费和 Windows 图标快照采集。
   - Windows 新记录在来源图标可解析时必须生成并同步快照。
   - macOS 可以消费由 Windows 同步来的快照，但本阶段不得宣称 macOS 已能为本机新记录生成快照。
2. 阶段 B：macOS 原生采集。
   - macOS 使用既有 `NSWorkspace`/App Bundle 解析结果生成相同格式的快照。
   - 完成 macOS 本机采集、跨设备同步和 Native AOT 验证后，才可把整个功能标记完成。

Linux 不在本次实施范围内。不得增加始终成功、始终返回空图标或伪造来源图标的平台实现。

## 3. 用户可见行为

1. 主窗口和快速窗口中，来源应用名称旁的小图标表示复制内容的来源应用；左侧内容类型图标不受本需求影响。
2. 来源设备成功取得原生应用图标后，另一台设备必须显示同步得到的图标，不能依赖原设备的 EXE/App Bundle 路径。
3. 目标设备上应用安装目录不同、应用未安装，或者目标设备是另一种操作系统时，均不得影响已同步快照的显示。
4. 显示优先级固定为：
   - 已持久化并验证通过的同步图标快照；
   - 当前设备能够根据本机身份重新解析出的原生图标；
   - Edge/VS Code 等既有明确备用图标；
   - 通用应用图标。
5. 同步快照是来源记录生成时的图标。目标设备不得用一个同名但不同应用的本地图标覆盖它。
6. 来源无法识别、权限不足、原生 API 返回空图标或快照校验失败时，剪贴板正文仍应正常保存和同步，只降级图标显示。
7. 本功能没有用户开关，不新增设置项，也不改变收藏、搜索、自动清理、全屏保护或快速窗口行为。

## 4. 标准快照格式

共享层只接受以下规范格式：

| 字段 | 要求 |
| --- | --- |
| 宽度 | 固定 32 像素 |
| 高度 | 固定 32 像素 |
| 像素格式 | BGRA8888，预乘 Alpha |
| 行跨度 | 固定 128 字节 |
| 像素长度 | 固定 4096 字节 |
| 媒体类型 | `application/vnd.snapboard.source-icon-bgra32` |
| 格式版本 | `1` |

不得同步 HICON、NSImage、ICO、ICNS、EXE、App Bundle 或平台句柄。平台实现必须先转换为规范像素，再交给共享层。

快照不得包含窗口标题、游戏名称、文档路径、剪贴板正文或其他来源应用状态。

## 5. 本地采集与持久化

1. 快照采集发生在正文已通过安全策略和内容规范化之后、历史写事务之前。
2. 原生剪贴板通知线程不得读取图标。Windows Shell、磁盘或 macOS AppKit 访问必须继续发生在后台/平台主线程调度边界内。
3. 图标采集失败不得使 `IClipboardContentReader.ReadAsync`、正文规范化或历史保存失败。
4. 对具有可解析身份但首次返回空图标的来源，允许一次有界短延迟重试；不得无限重试或阻塞原生消息线程。
5. SQLite 当前格式升级到 v9。每条历史记录最多引用一个来源应用图标 Blob，并保存格式版本、宽、高和 stride。
6. 像素通过既有内容寻址 Blob 存储，SHA-256 相同的图标必须复用文件并维护精确引用计数。
7. 删除、清空、自动清理、远端墓碑和失败回滚必须同步释放图标 Blob 引用。未被数据库引用的临时文件继续由既有孤儿清理处理。
8. 相邻重复记录合并时，已有有效快照优先保留；只有原记录没有快照时才补入新快照，避免无意义的引用替换。
9. 不回填旧数据库中的历史记录。本项目当前没有需要兼容的历史数据，不增加后台扫描、旧字段兼容或旧图标迁移代码。

## 6. 同步协议

1. 直接更新当前同步协议结构，协议版本号和远端根目录保持现状。
2. 不增加新旧协议兼容、双协议分支或远端空间迁移。本项目当前没有需要兼容的已部署同步数据。
3. `SyncClipboardItemPayload` 新增可空的 `SourceApplicationIcon` 描述符，包含：
   - Blob 哈希、媒体类型和长度；
   - 格式版本；
   - 宽度、高度和 stride。
4. 字段可空仅用于来源未知或原生解析失败。Windows 平台一旦取得有效图标，就必须写入该字段。
5. 图标 Blob 使用现有 keyed Blob ID、AES-256-GCM 信封、条件 PUT 和去重流程。服务端只能看到密文和密钥化对象名。
6. 事件上传前必须先上传图标 Blob；远端应用事件前必须先下载、解密、验证并暂存图标 Blob。
7. 目标设备应用远端事件时，图标 Blob、历史正文、SQLite 引用、Inbox 和 Checkpoint 必须处于同一原子提交边界。任一校验失败不得留下半条历史记录。
8. 远端校验必须拒绝：
   - 非规范媒体类型或格式版本；
   - 非 32×32、stride 非 128 或长度非 4096；
   - 非规范 SHA-256 哈希；
   - Blob 元数据与实际内容不一致；
   - 同一事件中同一哈希对应冲突媒体类型或长度。
9. 来源应用 EXE/App Bundle 路径仍不得进入同步 DTO、JSON、Outbox、远端 Blob 或日志。

## 7. Windows 阶段要求

1. 复用现有 `WindowsClipboardSourceApplicationMetadataResolver` 的 Shell/AppsFolder 解析结果，不建立第二套图标识别逻辑。
2. Win32 EXE 图标、MSIX/Store AppsFolder 图标和已存在的显示名称降级均保持有效。
3. Windows 原生图标必须转换为规范 32×32 BGRA8888 预乘 Alpha 快照。
4. 解析器进程缓存、并发上限、HICON/GDI/DC 释放和空结果不污染缓存的既有保证必须保留。
5. Desktop 组合根只在 Windows 注册快照提供器。macOS 阶段完成前不得注册 macOS 快照提供器。
6. Windows 本机记录和从其他设备下载的记录必须走同一套持久化快照显示路径。

## 8. macOS 阶段要求

1. 使用既有 `MacOSClipboardSourceApplicationMetadataResolver`、`NSWorkspace` 和 App Bundle 路径解析，不调用 Windows API。
2. AppKit 访问继续通过 `IPlatformMainThreadDispatcher`；不得在剪贴板轮询线程直接访问 `NSWorkspace`。
3. NSImage/CGImage 必须转换为与 Windows 完全相同的 32×32 BGRA8888 预乘 Alpha 数据。
4. Bundle 路径仅用于本机解析，不得同步。
5. macOS 生成的快照必须能在 Windows 显示，Windows 生成的快照必须能在 macOS 显示。
6. macOS arm64/x64 Native AOT、真实 TextEdit/Finder 来源以及跨设备往返验证通过后，阶段 B 才可完成。

## 9. 性能与安全边界

1. 单个规范快照固定 4096 字节；相同应用图标通过内容哈希去重。
2. 图标解析仍使用现有 256 项有界缓存和平台并发限制，不增加全局键盘 Hook、窗口标题读取或额外剪贴板监听。
3. UI 只为进入虚拟化视口的记录按需读取 Blob 和创建 Avalonia Bitmap。
4. UI 线程不得执行文件读取、SHA-256 校验、Shell/AppKit 解析或远端访问。
5. 解析、持久化和同步异常不得把路径、正文或原生错误详情写入用户可见状态或普通日志。
6. Native AOT 发布必须保持 0 个未解释 trim/AOT 警告。

## 10. 自动验证

阶段 A 至少覆盖：

- Windows EXE 与 AppsFolder 图标生成规范快照；
- 快照提供器异常、空图标和一次重试均不阻断正文保存；
- SQLite v9 创建、重复迁移和失败回滚；
- 图标 Blob 的去重、重启读取、相邻重复补入、删除、清空、自动清理和引用计数；
- 当前 JSON 契约的源生成往返及未知字段拒绝；
- Outbox 包含图标描述符，图标 Blob 先于事件上传；
- 远端下载、哈希/长度/格式校验、原子应用和墓碑清理；
- 两个不同安装路径的模拟设备仍显示相同像素；
- 目标设备没有来源应用时仍显示快照；
- 同步快照优先于本机原生解析器，坏快照降级且不崩溃；
- 主窗口和快速窗口继续显示来源名称、快照与通用回退；
- 完整解决方案 Release build/test 和 Windows `win-x64` Native AOT。

阶段 B 至少覆盖：

- macOS App Bundle 原生图标生成规范快照；
- AppKit 主线程边界和缓存复用；
- macOS -> Windows、Windows -> macOS 像素往返；
- macOS arm64/x64 Release test 和 Native AOT；
- 真实 TextEdit、Finder 以及未安装来源应用场景。

## 11. 实机验收

Windows 阶段必须使用全新数据目录验证：

1. 从 Chrome、Edge、微信、资源管理器和一个 MSIX/Store 应用复制内容。
2. 主窗口与快速窗口显示正确来源图标。
3. 把记录同步到另一份隔离数据目录；不得复制原应用路径或预装相同应用作为验收前提。
4. 目标目录中的记录显示与来源快照相同的像素。
5. 删除记录后图标 Blob 引用和文件按既有生命周期正确清理。

macOS 实机验收在阶段 B 单独执行，不得用 Windows 自动测试推断通过。
