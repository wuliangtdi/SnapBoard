# SnapBoard WebDAV 同步协议

> 协议状态：v1 已实现。Windows 端已完成本机创建/加入空间、端到端加密上传下载、双设备合并和 Native AOT 验证；Nextcloud、群晖与 Apache 等真实服务兼容矩阵仍待验收。

## 1. 设计原则

- 不同步 SQLite、WAL、缓存和本地索引文件。
- 每台设备只写自己的远端事件目录，远端事件和 Blob 创建后不可修改。
- 服务端只保存密文；WebDAV 地址、用户名、密码、证书指纹和恢复码属于设备本地凭据，不作为设置事件同步。
- 客户端可离线工作，恢复连接后按设备序列幂等合并。
- 同步 Text、HTML、RTF、Image 和文件引用；文件本体不上传。
- 历史记录策略属于空间配置，删除结果属于历史数据，两者都必须跨设备收敛。

## 2. 远端布局

用户设置的远端根目录默认是 `SnapBoard/v1`，其下布局如下：

```text
SnapBoard/v1/
  spaces/
    <space-id-n>/
      metadata.enc
      devices/
        <device-id-n>/
          events/
            <20-digit-sequence>-<event-id-n>.enc
          checkpoints/                 # 为后续远端检查点保留
      blobs/
        <keyed-content-hash>.enc
```

`space-id`、`device-id` 和 `event-id` 使用无连字符的小写 GUID。Blob 名称是 64 位小写十六进制密钥化内容标识，避免服务端通过公开内容哈希猜测常见剪贴板内容。

## 3. WebDAV 操作

| 操作 | 用途 | 约束 |
| --- | --- | --- |
| `MKCOL` | 创建空间、设备、事件、检查点和 Blob 目录 | 已存在视为幂等成功 |
| `PROPFIND Depth: 1` | 枚举设备和事件 | 只接受规范化的直接子项，限制响应大小和 XML 深度/数量 |
| `GET` | 下载元数据、事件和 Blob | 限制最大长度，随后验证加密信封和认证标签 |
| `PUT` + `If-None-Match: *` | 创建不可变元数据、事件和 Blob | `412` 后读取并验证已存在对象，禁止覆盖 |

协议不依赖 `LOCK`。正确性由设备独占事件目录、不可变对象、严格序列和条件写入共同保证。WebDAV 端点默认必须使用 HTTPS；证书固定只允许匹配的 SHA-256 指纹，不会绕过主机名错误。

## 4. 本地到远端

```mermaid
flowchart LR
    Change["历史或设置写事务"] --> Outbox["同事务追加 Outbox"]
    Outbox --> Json["源生成 JSON"]
    Json --> Encrypt["AES-256-GCM 加密信封"]
    Encrypt --> Put["条件 WebDAV PUT"]
    Put --> Ack["标记 Outbox 已上传"]
```

历史新增、置顶、删除、恢复以及受支持的设置变更，都在业务写事务中追加不可变事件。事件引用的 Blob 先上传，事件上传成功后才标记对应 Outbox 项；超时或对象已存在时读取远端内容验证，不能盲目覆盖。

## 5. 远端到本地

1. 枚举空间中的设备目录，跳过本机设备。
2. 从本地逐设备 Checkpoint 的下一序列开始枚举事件。
3. 要求事件连续递增；缺号、重复序列或非法对象名均按协议错误处理。
4. 限长下载并验证空间、设备、序列、对象标识、密钥版本和 AES-GCM 认证标签。
5. 使用 `SyncJsonContext` 反序列化并进行事件形状校验。
6. 先暂存缺失 Blob，再在 SQLite 事务中幂等应用 Inbox、业务数据和 Checkpoint。
7. 事务提交后更新运行时设置或通知历史 UI 刷新。

## 6. JSON 契约

- 唯一实现是 `System.Text.Json` 源生成。
- DTO 使用 camelCase、明确协议版本和稳定枚举数值。
- 新增 DTO 必须加入 `SyncJsonContext` 的 `[JsonSerializable]`。
- 不使用 Newtonsoft.Json、动态类型、类型名元数据或运行时反射。
- 未登记字段会被拒绝；未知协议版本或未知枚举值也会被拒绝。

## 7. 历史与设置一致性

### 7.1 历史事件

- 新增记录使用 `Upsert`，`EventId` 与 Inbox 保证幂等。
- 自动清理、手动删除和清空产生普通 `Delete` 墓碑，并通过同一加密事件流同步。因此一台设备按保留期清理后，其他设备最终也会删除相同记录。
- 自动清理默认不删除收藏内容；用户可在历史设置中关闭“自动清理时保留收藏内容”，此时收藏也按保留期参与清理。收藏、标签等可变元数据使用逻辑版本和确定性 LWW，相同逻辑时间以 `DeviceId` 稳定排序。
- Blob 缺失时事件不会以破损内容提交到历史列表。

### 7.2 空间设置

当前同步以下设置键，不保留旧键兼容层：

| 设置键 | 内容 | 默认值 |
| --- | --- | --- |
| `history.capture` | 是否记录文本、HTML/RTF、图片、文件/文件夹引用 | 全部开启 |
| `history.retention` | 是否自动清理、保留天数及是否保留收藏 | 自动清理关闭；保留收藏开启 |
| `sync.pollInterval` | 无本地变化时检查其他设备的间隔 | 5 分钟 |

设置使用 `SetSetting` 事件，`ItemId` 固定为空 GUID，设置正文随事件加密。SQLite 为每个设置键保存 `(LogicalTimestamp, DeviceId)`，逐键执行确定性 LWW，避免一个设置覆盖另一个设置。创建新空间时会发布当前设置；加入空间后下载到的更新会立即应用到运行时采集、清理与同步调度器。

以下内容有意保持设备本地，不进入设置同步：WebDAV URL、远端根目录、用户名、密码、证书指纹、空间主密钥和一次性恢复码。恢复材料文件用于把空间主密钥安全带到另一台设备，不是普通偏好设置。

## 8. 调度

- 本地历史或同步设置变化后立即请求后台同步，并按有界批次上传；该路径不等待轮询周期。
- 应用启动和用户手动操作立即触发拉取。
- 没有保存 `sync.pollInterval` 时每 5 分钟检查一次远端；设置页可选 30 秒、1/5/15/30/60 分钟，修改后当前进程立即生效并同步到其他设备。
- WebDAV 没有统一推送，因此产品只承诺最终一致，不承诺实时一致。
- 自动清理默认关闭；开启后在启动、策略变化和每日维护时运行，也可由用户手动触发。

## 9. 验证边界

假远端双设备端到端测试已覆盖空间创建/加入、加密事件与 Blob、设置收敛、重复收发、删除墓碑和暂停排空。真实 Nextcloud、Synology WebDAV Server 和 Apache `mod_dav` 仍需逐项验证；服务端不支持标准条件写入、规范 `PROPFIND` 或可靠对象读取时，客户端必须显示具体诊断，不能静默退化为覆盖写入。
