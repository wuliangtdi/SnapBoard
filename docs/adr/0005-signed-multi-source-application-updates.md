# ADR-0005：签名的多源应用更新

- 状态：Accepted
- 日期：2026-07-29

## 背景

SnapBoard 需要在 Windows、macOS 和 Linux 上支持应用内检查、下载和安装更新，并允许用户在
GitHub Release 与未来的自建官方源之间选择。更新源和 CDN 都不能被当成发布身份本身；即使 HTTPS
连接成功，客户端仍必须证明更新清单确实由 SnapBoard 发布者签发，并在多个可信源不一致时停止。

应用安装目录与每用户数据目录已经分离。更新流程必须保持剪贴板采集、同步排空、SQLite、Blob、
恢复材料和系统安全存储的现有边界，不能通过覆盖程序文件来隐式迁移或删除用户数据。

## 决策

### 1. 更新引擎与通道

使用锁定为 1.2.0 的 Velopack 负责安装布局、版本比较、包下载和退出后替换。`VelopackApp.Run()`
必须是 Desktop `Main` 的第一段框架代码，启动时关闭自动套用；只有用户确认安装后才安排退出替换，
避免在同步或持久化仍在运行时直接覆盖程序。

通道同时隔离操作系统、进程架构和发布等级：

```text
win-x64-stable      win-x64-beta
osx-arm64-stable    osx-arm64-beta
osx-x64-stable      osx-x64-beta
linux-x64-stable    linux-x64-beta
```

包 ID 也包含 RID，防止同一 GitHub Release 中不同架构生成同名资产。禁止跨架构或从测试版隐式切换
到稳定版；通道选择由用户本机设置决定，不进入 WebDAV 同步协议。

### 2. 多源选择与冲突规则

用户可以选择自动、官方源或 GitHub。自动模式读取所有已配置来源并合并经过签名验证的 feed；
某一来源暂时不可用时可以使用其他来源。若多个可信来源对相同包 ID、版本和资产类型给出不同文件名、
SHA-256 或长度，必须以源冲突失败，不能按优先级静默选择。

下载时按已验证候选源回退。失败源留下的部分文件先删除，再尝试下一个候选。官方源只接受无凭据、
无 query/fragment 的 HTTPS 基地址。当前正式构建没有部署自建官方源；只有明确设置
`SNAPBOARD_UPDATE_OFFICIAL_BASE_URL` 时才启用该来源。

### 3. 应用级签名

每个 `releases.<channel>.json` 使用独立 ECDSA P-256/SHA-256 DER 签名，签名文件为同名 `.sig`。
客户端内置 SubjectPublicKeyInfo 公钥，feed 大小、签名大小、文件名和 UTF-8 都有严格限制。
只有 feed 验证成功后，Velopack 才能读取其中的资产；完整包继续按签名 feed 中的 SHA-256 和长度
验证。签名失败、包校验失败或 feed 路径异常都拒绝更新。

仓库只提交公钥。发布私钥不属于任何客户端或终端用户，只保存在维护者的仓库外受限文件和
GitHub Secret `SNAPBOARD_UPDATE_SIGNING_PRIVATE_KEY_PEM` 中。发布脚本要求私钥没有组/其他用户
读取权限，并先证明私钥与提交的公钥匹配，再生成和复验签名。

Windows 代码签名证书与 macOS Developer ID/公证是独立的操作系统信任层。它们不是应用级 feed
签名的前置条件，但缺少它们会产生 SmartScreen/Gatekeeper 警告，因此未签名或 ad-hoc 包只能作为
开发验证产物，不能标为正式发布。

### 4. 检查、下载与安装生命周期

应用启动后延迟 30 秒执行首次自动检查，之后每 12 小时检查一次。设置页允许保存自动检查开关、
稳定版/测试版和来源，并提供手动检查、下载、进度及“安装并重启”。设置只存入本机通用设置表，
不包含秘密，也不通过当前加密同步设置传播。

安装前 Desktop 生命周期先暂停并排空同步，再暂停剪贴板采集，然后调用 Velopack 安排退出后替换并
明确退出应用。任何安排失败都恢复原采集和同步状态。启动时不静默安装已下载版本。

### 5. 数据保护与发布回退

Velopack 只管理应用安装目录。SQLite、Blob、恢复材料和平台凭据继续位于权限受限的每用户数据根；
本功能不修改数据库 Schema，也不把用户数据复制进更新包。

客户端禁止自动降级。错误版本的常规恢复方式是撤下有问题的 feed，并以更高 patch 版本发布已知
良好的修复，即 roll-forward。若未来版本包含不可逆数据库迁移，发布前必须新增迁移前备份、恢复、
旧版本读取边界和失败演练；在这些能力完成前不得通过自动更新发布该迁移。

## 后果

- 所有终端只需要公开验证密钥；私钥泄露面限制在发布者和 CI。
- GitHub 与未来官方源可以互为可用性回退，但不能掩盖同版本内容冲突。
- 从旧的手工压缩包或现有 DMG 安装的版本不具备 Velopack 安装元数据，必须先使用一次新的
  Velopack Setup/AppImage，之后才能自更新。
- 当前已验证签名 feed、包生成、AOT 和未安装状态；Windows 已安装升级、Developer ID 正式 macOS
  升级、Linux 真实发行版升级、远程 Release workflow 和自建官方源仍是发布前实际验证项。
